# 🕷 SCRAPER MODULE RULES (Playwright)

## 🛠 ТЕХНОЛОГИЧЕСКИЕ ПРАВИЛА
- **Isolation:** Разделяй логику на отдельные провайдеры (папка `providers/`). Один сайт — один провайдер.
- **Validation:** Данные, полученные из браузера, **обязаны** проходить через `.parse()` соответствующей Zod-схемы перед возвратом из модуля.
- **Automation Focus (Cron):** Все методы скрапера должны быть оптимизированы для вызова через **Cron**.
    - Запрещено требовать ручного взаимодействия с пользователем (инпуты, решение капчи вручную и т.д.).
    - Предусматривай автоматические повторные попытки (retries) при сбоях сети с backoff и jitter.
    - Явно задавай таймауты навигации/ожиданий и общий таймаут задачи.

## 🛡 БЕЗОПАСНОСТЬ И РЕСУРСЫ
- **Lifecycle Management:** Всегда используй блок `try...catch...finally`. В блоке `finally` обязательно вызывай `await browser.close()`, чтобы избежать утечек памяти (зомби-процессов) в Docker-контейнере.
- **Error Handling:** Ошибки парсинга конкретного поля или страницы не должны приводить к краху всего процесса. Используй локальную обработку ошибок для каждого шага.
- **Headless Mode:** По умолчанию скрапер должен работать в `headless: true`, так как он запускается в среде без графического интерфейса.
- **Stealth:** Используй стандартные заголовки и настройки эмуляции, чтобы минимизировать риск блокировки при автоматических запусках.
- **Logging:** Логируй старт/финиш провайдера, количество полученных сущностей, а также причины частичных фейлов с `jobId`.
